## Performance bug found during final visual audit

Detailed PageSpeed output exposed React error 418 and identified the hero heading as the LCP element. Reproducing the site in `America/Los_Angeles` changed Eagle's date-only `2026-10-15` into 14 October after hydration, regenerating the client tree. Inspection dates now format with an explicit UTC calendar interpretation; the advertised local time remains unchanged. Eight tests pass, including inspection-date stability across Melbourne, Los Angeles, Honolulu and UTC, and a daylight-saving transition date. This fixes the mismatch rather than suppressing its warning. See [React's error explanation](https://react.dev/errors/418).

PageSpeed also identified oversized property-card and header-logo resources. The catalogue preparation now produces cached 360/720/1080-pixel WebP derivatives, capped at the source's natural width, and cards select them through `picture`/`srcset`. Property galleries retain their larger genuine photographs. The supplied horizontal logo has proportion-preserving 240/480-pixel WebP derivatives. The first listing below the homepage hero is no longer eagerly preloaded ahead of the hero. No additional runtime service or image-hosting subscription is required.

Static homepage sections now render at build time outside the client wrapper. Interactive property previews receive only three current listings per transaction type and four sold/four leased examples, plus independent full-catalogue counts. The full `/buy`, `/rent` and `/sold` catalogues remain available on their respective pages. Navigation no longer prefetches eight destination pages during the initial hero load. Filter controls are native toggle buttons with pressed state. A manually triggered refresh on the new implementation passed on 14 October: [refresh workflow run](https://github.com/kloudocean-kodex/krish-real-estate/actions/runs/38460736415). An actual unattended scheduled firing also passed, as recorded above.

Initial homepage script payload fell from 786,476 to 632,030 bytes uncompressed (217,015 to 194,513 bytes when locally gzip-compressed). These are script-only build measurements, not a claim about total transfer size or field Core Web Vitals. The featured listing grid also uses the shared progressive reveal behaviour, so its content is visible before the animation script runs.

Latest measured [PageSpeed report](https://pagespeed.web.dev/analysis/https-krishrealestate-com-au/hg5meaqa3t?form_factor=mobile): desktop performance 100, mobile performance 82 under slow-4G simulation; accessibility, best practices and SEO 100 on both. Desktop LCP 0.7s, mobile LCP 3.9s, CLS 0 on both. This measurement was taken on `94a01a5`; later changes only corrected results-card reveal alignment and the owner's requested visible captions/control. No CrUX field data was returned. Mobile heading render delay remains a further performance opportunity; these scores are not a promise of perfect performance on every device or connection.
